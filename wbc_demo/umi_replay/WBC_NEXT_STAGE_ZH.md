# 从当前 UMI 全身 IK 到 WBC：分阶段路线

**2026-10-19 更新**：已开展同步误差日志、可选 Pinocchio 在线对照与多 episode 批测，见 [实际进展/失败记录](ONLINE_AB_RESULTS_ZH.md)。已复现接近限位的制动可行性问题和超时 HOLD 名义加速度跳变；应优先补可行域/降级连续性，再升级闭环增益。下文保留最初路线的阶段划分。

## 0. 当前起点与本轮已经执行的任务

当前是固定底盘、固定头部、腰部＋双臂＋夹爪的 30 Hz 软实时**位置级微分 IK**，不是动态平衡或力矩 WBC。
本轮先审计代码并修复有测试复现的问题，再做 Pinocchio 模型级探测；不直接解锁底盘或更换在线控制后端。

- 已执行：[代码审计与修复记录](CODE_AUDIT_ZH.md)。
- 已执行：[Pinocchio 可行性与实测](PINOCCHIO_STUDY_ZH.md)，100 个实际状态模型对照及单步 QP 测试通过。
- 本轮没有完成：Pinocchio 实际闭环 A/B、多 episode 通用性、真实力矩控制、轮地接触 WBC。

## 1. 先分清三个层次

| 层次 | 决策变量/输出 | 当前是否具备 |
|---|---|---|
| 运动学全身 IK | 关节位置或速度，让双手及腰部协调 | 有基线；缺少成熟闭环/故障覆盖 |
| 移动操作的运动学 WBC | 再加入底盘运动，与双手/腰部联合分配动作 | 未解锁；需要轮式运动约束 |
| 动力学 WBC | 加速度、关节力矩、接触力，满足动力学与接触约束 | 未实现；位置命令不能冒充力矩输出 |

对 VLA 工程应用，先做好前两层通常更快获得可用接口；是否做第三层由力控/接触任务需求决定。
下面是本项目的工程路线，不是某个开源项目已经替我们完成的功能。

### 建议采用的方法长什么样

**运动学阶段：双手联合微分 IK QP。** 用同一组关节速度 `v` 同时满足左右手任务，而不是左右臂分别求解后争抢腰部：

```text
min_v  Σ手 ||J手(q) v - (目标速度 + K × 位姿误差)||²_权重
       + 姿态偏好 + 速度正则
s.t.   关节位置/速度边界、离散加速度边界、机构耦合
       + 经验证的距离/底盘运动约束
```

`q` 是机器人关节状态，`J` 把关节速度映射到 EEF 速度，`K` 是误差收敛增益。上式是下一阶段闭环方法的概念形态，
不是声称当前已经实现实测闭环、所有距离约束或底盘约束。位置和姿态误差单位不同，任务权重需要明确缩放，不能直接拼接后当成同等重要。
对于当前标量关节可做小步积分；以后涉及浮动基座或圆周配置时使用模型的配置积分，不直接对四元数相加。

安全/机构约束放在硬约束，直腰通常先做软偏好。`roll ±0.5°` 可作为任务特定的硬限制或对照实验，
**不是“全身 IK 必须如此”的通用规律**：它会缩小可行域，任务不可达时应明确拒绝/降级，不能偷偷违反其他限位来保持直腰。
加权 QP 表示任务折中，不等于严格层级；如果后续需要“第一优先级不能为第二优先级牺牲”，再评估 HQP/词典序优化。

**动力学阶段：逆动力学 QP。** 优化变量改为加速度 `a`、关节力矩 `τ` 和接触力 `λ`，必须满足：

```text
M(q) a + h(q,v) = Sᵀ τ + J接触(q)ᵀ λ
```

`M` 是质量矩阵，`h` 包含重力/速度相关项，`S` 选择可驱动关节，`J接触` 把接触力映射为广义力。
此外还要有力矩限幅、接触运动学、法向力/摩擦及轮子滚动条件。双手跟踪和姿态偏好只是其中的任务，不能替代这条动力学方程。
固定基座和轮式浮动基座的约束不同；先在固定基座验证接口与模型，再引入接触，是降低调试歧义的选择。

## 2. 第一里程碑：可回归的固定底盘控制基线

**目标**：先证明现有实现不是只对一段数据“恰好能跑”。

1. 固定 episode 000 的世界变换，先测 000/001/002，再覆盖已下载的 11 段；不逐段偷偷平移/缩放以提高成功率。
2. 对比软直腰/roll ±0.5°；对比一帧前瞻与无前瞻，明确文件回放与因果在线输入的差别。
3. 记录 EEF 位姿、夹爪、底盘漂移、最小关节余量、QP 状态、计算耗时、超时与停止原因；失败也必须进入汇总。
4. 故障注入：碰撞服务延迟、丢失反馈、源目标中断、暂停/恢复、停止、不可达目标、接近限位/奇异点。
5. 不把“提前安全停止”计为完整轨迹成功；安全停止是否正确是另一项测试。

**验收门槛**：保持当前硬限位/耦合/碰撞与 EEF 误差保护，源时钟 1× 不被计算积压拖慢；视频仍按原 100 ms 相位匹配阈值验收。
每个 episode 独立保存报告，给出失败比例和原因，不预设 11 段都能在当前布置下可达。

## 3. 第二里程碑：Pinocchio 统一模型与真正的闭环伺服

**先换模型，后换控制律，避免无法归因。**

1. 保留原模型作为 oracle，Pinocchio FK/Jacobian 与全部被采样状态对照；固定 EEF、mimic、关节名/索引、参考系契约。
2. 在完全相同的目标、QP 权重、约束和物理场景下跑实际 A/B；通过后才允许把 Pinocchio 作为可选在线后端，不直接设默认。
3. 引入实测位置/速度与时间戳；从“上一命令积分＋误差监控”逐步升级为实测状态驱动的闭环。
4. 将任务增益与控制周期分离；评估约束可行域、限位制动余量、奇异性阻尼和稳定的暂停/恢复状态。
5. 小范围评估 Pink：双手 FrameTask、姿态偏好和自定义 G2 线性耦合限制。自定义不等式不能只用一个软代价替代。

**验收门槛**：相同轨迹下约束不丢失、误差/延迟/停止行为不回退；对受控小扰动，能解释并测量误差恢复，而不是靠继续播放文件掩盖偏差。
Pinocchio 只缩短模型计算；同步 ROS 碰撞调用与 Python 调度仍可能主导周期。当前约 0.23 ms 的 FK/Jacobian P95 不意味着已经能跑 1 kHz 控制。

## 4. 第三里程碑：接 VLA / UMI 在线目标流

把文件回放器变成一个“目标提供者”，与控制器解耦：

```text
VLA / UMI 文件 / 交互目标
  → 双手 EEF 目标 + 开度 + frame_id + 时间戳 + 有效期
  → 最新有效目标缓存，拒绝过期/乱序目标
  → 插值、限幅、闭环全身运动学控制
  → 原有状态/碰撞监控与位置接口
```

- 固定相机视频播放、目标时钟和机器人反馈各自的契约，不能拿显示帧率等同控制频率。
- VLA 低频输入与伺服高频执行分离；高频环可先以 100 Hz 为实验目标，必须实测截止时间，不预先承诺达到。
- 真正在线输入不依赖未来一帧；目标超时进入保持/安全停止，不执行过期队列。
- 沿用 Web 操作和 2×2 可视化，不新增 PyQt/PySide 依赖。

## 5. 第四里程碑 A：轮式底盘参与运动学 WBC

先验证底盘真实驱动模型。仓库有 4WS 相关命令路径，但仍需核对所用 G2 资产和硬件接口，不能直接假定任意 `vx/vy/yaw_rate` 都可执行。

1. 底盘先单独做直线/转向/刹停与里程计一致性测试，再让腰部、双臂和底盘共同优化。
2. 把轮半径、转向限位/速率和滚动/不可侧滑关系写进约束，不用直接改根位姿模拟“会开车”。
3. 做同一任务的“底盘固定 vs 底盘参与”对照，统计腰/臂余量、底盘路径、EEF 跟踪和停止距离。
4. 地面、障碍物、里程计与世界坐标必须一致；先有碰撞/定位，再谈长距离 VLA 操作。

这里得到的是移动操作的运动学协调，不自动具备接触力分配和动态防倾覆。

## 6. 第四里程碑 B：固定底盘逆动力学，再进入轮地接触 WBC

这是与 A 分开的研究分支，不要求先让轮子跑起来。

### 先检查接口，不能把力矩算出来就叫力控

当前控制器只发送位置。引擎文档描述 PhysX 位置 PD；`kit/stage.py::_apply_joint_commands` 的当前入口是位置和底盘速度字典，
没有让本回放器直接发送关节力矩的已验收路径。内部出现 `joint_efforts` 字段并不意味着端到端力矩接口已经打通。

需要先建立独立受控的 effort 通道，核对单位、符号、关节映射、限幅/看门狗，正确处理位置驱动刚度/阻尼，避免 PD 与外部力矩互相打架。
顺序应是：固定底盘重力补偿 → 单臂小幅阻抗/抗扰 → 双臂＋腰逆动力学 → 才加入轮地接触。
若实机只有位置接口，就保持诚实的运动学 WBC/外环参考生成，不把仿真中的力矩能力外推到实机。

### 方法与验收

- 用 Pinocchio 计算质量矩阵/非线性项；先核对 URDF 与 PhysX 的质量、惯量、轴方向及传动约束，模型正定不等于参数正确。
- 评估 TSID / PlaCo 逆动力学任务层。固定基座先求关节加速度/力矩，接触模型成熟后再处理轮地接触力。
- 接触 WBC 需要动力学方程、力矩边界、法向力与摩擦约束、滚动关系以及任务优先级，不能只加一个 COM 软目标就宣称不会倾覆。
- 检查手腕外载与地面反力；固定焊接底盘的实验不能证明真实轮式平台的抗倾覆能力。
- 力矩环频率与实时核心另行设计和实测；当前 Python/ROS 服务式 30 Hz IK 不能直接复制为高频力矩控制。

[TSID 官方项目](https://github.com/stack-of-tasks/TSID)提供基于 Pinocchio 的优化逆动力学；[PlaCo 官方项目](https://github.com/Rhoban/placo)同时提供运动学与逆动力学接口。
这是选型候选，不是已在本平台验证的控制结果。
